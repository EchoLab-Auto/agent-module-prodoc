# 写盘与冲突

`write::save` / `write::delete` 与 ProDoc CLI 的 `write-api.ts` 逐条对齐。核心决定是：
**冲突判定用逐字比对，不引入版本号 / mtime / hash。**

## 为什么是逐字比对

CLI 的判据是 `current !== base`（整篇字符串全等）。看着笨，但有个好性质：不需要维护版本号，
客户端把「我看到的内容」原样带回来即可。换 mtime 会在 `git checkout` / `touch` / 网络盘
时间抖动上误报；换 hash 需要额外存储，且同样对「内容没变但时间变了」无能为力。

代价是**原文必须逐字保留**（见 [扫描与上限](./scan.md)）：读取不做任何修剪。

## 保存的四个分支

| 输入 | 磁盘 | 结果 |
|---|---|---|
| `base = None` | 任意 | 无条件覆盖（新建文件走这条：调用方明确表示「我知道我在覆盖」） |
| `base = X` | 已等于 `content` | **幂等成功**（放弃更改 / 网络重放不该变成冲突） |
| `base = X` | 已等于 `X` | 原子写 |
| `base = X` | 不存在 | 冲突，`disk = None`，**不重建** |
| `base = X` | 其它内容 | 冲突，`disk = 磁盘当前内容`，不写盘 |

「文件已被删 + base」特意不重建：重建等于撤销别人的删除，且用户看不到这件事。

`delete` 同理：文件已不存在 = 目标达成（幂等成功）；带 `base` 且内容不符则取消删除，回执
附磁盘内容。删除**不做合并**。

## 原子写

同目录临时文件 + `rename`。`rename` 失败时清掉临时文件，否则每次失败都在文档目录里留一个
隐藏文件。

直接 `write` 在进程中断时会留下半截文档——对 `.md` 来说那不只是「读到一半」，而是**参数区
被截断**：下次扫描会把它当成没有参数区的文件、节点 id 从文件名推断，图上的连线就全断了。
这是 `.md` 特有的风险，也是这里必须原子写的原因。

## 三路合并不在这里

CLI 冲突时会 `merge3(base, current, content)`，干净就自动写盘。本模块**刻意不实现** diff3：

- 那 265 行（hunk 级 diff3 + LCS）复刻到 Rust 必然与 `prodoc-core/merge.ts` 语义分叉，
  结果是「面板说合并成功、命令行说冲突」
- 前端本来就带着这份实现（vendored 的 `@prodoc/core`）

所以职责是：冲突时把磁盘内容原样回给前端（`WriteAck::disk`），由前端跑 merge3，干净就以
`base = disk` 重发一次。两次往返，语义与 CLI 完全一致。前端那一侧见
[面板 UI](./panel-ui.md)。

## 路径沙箱

`paths::resolve` 是读写共用的唯一入口，三重防护与 CLI 的 `resolveSafeDocPath` 一致：

1. **根内前缀**：`canonicalize` 后比较，前缀带分隔符（`/docs` 不匹配 `/docs-old`）
2. **只允许 `.md`**：后缀大小写不敏感
3. **父目录 realpath 仍在根内**：前两重都只看字符串，根内一个指向 `/etc` 的软链就能把写入
   引到根外

另外：空路径 / 绝对路径 / 含 `..` 一律拒绝，`\` 也按分隔符检查（Linux 上它只是文件名字符，
不统一处理会让 `a\..\..\etc\passwd` 在跨平台场景绕过检查）。父目录不存在时报 `NoParent`
而不是去创建目录。

## 回执

三种操作共用 `WriteAck`（见 [事件协议](./events.md)）：`ok` / `error` / `conflict` / `disk` /
`content` / `request_id`。命令层只负责把 `WriteOutcome` 翻译成回执并发对应事件，
判定全在 `write.rs`。
